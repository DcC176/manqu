FEATURES

四个不妥协的地方

这类插件最容易翻车的地方是「看起来像，但一眼假」。下面四件事决定了它像不像直播间自己长出来的。

30s
判定窗口，同一句话的重复计数区间
3s
采样真实弹幕样式并应用给模拟弹幕
4px
拖动判定阈值，小于即视为点击
1
唯一申请的权限：storage

只认真实重复

30 秒滑动窗口统计同一句话的出现次数，达到阈值才判定为刷屏。短句（≤3 字，如「666」）阈值自动抬高——那更可能是自然互动，不是独轮车。

跟随直播间的样子

每 3 秒采样真实弹幕的字号、字重、描边、字体族与颜色分布。以白色为主的直播间模拟出来也以白色为主，偶尔的彩色只会偶尔出现。

画在弹幕区

画布对齐弹幕容器而非 <video>。视频有黑边时不会画进黑边里；网页全屏、窗口缩放、真全屏都能跟着对齐。

面板不挡路

右下角悬浮球，点击开合、按住拖动。展开方向按可用空间自动翻边，出界就换一侧。位移超过 4px 才算拖动，拖完松手不会误触。

HOW IT WORKS

从一条真实弹幕，到一片模拟弹幕

全程只读页面已有的 DOM，不发一个字节出去。刻意没有走 WebSocket 解析——B 站弹幕包在 ver=3 时是 brotli 压缩，浏览器原生解不开，引解码器要涨几百 KB，而聊天区早就有了同样的文本。

01

采集

MutationObserver 监听聊天区，只读 data-danmaku 与时间戳，不修改页面任何节点。

02

计数

文本归一化后进入 30 秒滑动窗口，按 B 站自己的 data-id_str 去重，聊天区重渲染不会重复计数。

03

判定

达到阈值即进入生成池；按文本长度分档抬高短句门槛。25 秒没有新的真实重复，自动淘汰出池。

04

重放

按「密度」从池中取出文本，投放到独立 canvas 上滚动。模拟弹幕不参与识别，不会自我放大。

SCREENSHOTS

两件东西：一张卡，一个球

参数只有三个：开关、密度、判定阈值。所有改动即时生效，不需要刷新页面。

安装步骤

  1. 下载 .crx 文件，不要解压。
  2. 地址栏打开 chrome://extensions（Edge 为 edge://extensions）。
  3. 打开右上角的开发者模式。
  4. 把 crx 文件直接拖到页面空白处，在弹窗里确认添加。
  5. 进入任意直播间，右下角出现悬浮球即安装成功。

支持范围：Edge 与多数 Chromium 系浏览器接受拖入安装。Chrome 稳定版已关闭非 Chrome 应用商店来源 crx 的安装通道，拖入会被浏览器直接拒绝——这是安装策略，与文件签名无关。 若你使用 Chrome，可在仓库页 Code → Download ZIP 取源码后，用「加载已解压的扩展程序」载入。

FAQ

常见问题

还有疑问，可以在仓库的 Issues 里提问。

主播和其他观众能看到我刷的内容吗？

不能。模拟弹幕只绘制在本机浏览器创建的一块 canvas 上：不写入页面 DOM、不调用任何 B 站接口、不建立 WebSocket 或 HTTP 连接。插件的网络请求数为 0，因此从服务端到其他观众，都不存在这份数据。

唯一的例外是你自己截图或录屏分享出去——那部分内容会出现在画面里。

为什么 Chrome 不让我拖 crx 安装？

Chrome 稳定版只允许安装来自 Chrome 应用商店的扩展，非商店来源的 crx 会被直接拒绝。这与文件是否签名无关，是浏览器侧的安装策略。

可行路径有两条：换用仍接受侧载的 Chromium 系浏览器，或从仓库取源码后用「加载已解压的扩展程序」手动载入。代价是需要打开开发者模式，好处是不依赖任何商店审核。

它会把我的判定越刷越多，形成自我放大吗？

不会。模拟弹幕渲染在独立 canvas 上，不是 DOM 节点，采集器只看聊天区里的真实弹幕，因此插件生成的文本永远不会回流进判定池。

为什么进直播间没反应，面板显示「捕获 0」？

说明当前聊天区没有新弹幕。插件不模拟「无中生有」，只有直播间本身在动，它才有素材可跟随。换一个人多的直播间，或等房间开始有互动即可。

如果换了房间仍然一直是 0，可能是 B 站改版导致聊天区选择器失效——这类问题需要在仓库提 issue，附上房间号与浏览器版本。

更新扩展后为什么没生效？

Chrome 不会把新版 content script 重新注入已经打开的标签页。更新后请刷新直播间页面：旧脚本会在约 1 秒内自行退出并清除自己的界面，不会报错也不会残留。

怎么彻底卸载？

打开 chrome://extensions，找到「满区」，点「移除」。设置保存在浏览器本地存储里，会随移除一并清除；下载的 crx 文件可以直接删除。
